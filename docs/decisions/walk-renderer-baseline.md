# Walk renderer baseline and software fallback

2 November 2026. The route study has 39 outlined spaces and 17 source-feature-referenced openings. The private plans and test project remain ignored by Git.

**Decision:** Keep the full raster scene on the Apple M1. On a WebGL context that reports SwiftShader, Walk uses a 0.5 pixel ratio, omits decorative landscape models and photographic texture maps, draws installed asset footprints as simple boxes, and disables the shadow pass. The same spatial model supplies all walls, gaps, floors and stair treads. A Blender export loads the full asset models on demand, so the software preview does not silently replace export geometry. No new library was added.

**Alternatives and experiment:** At an 880 × 720 CSS viewport, the in-app browser reported `ANGLE Metal Renderer: Apple M1`. A five-second held-W sample at 1760 × 1440 render pixels measured **18.6 ms** p95 between frames, **457** draw calls and **1,041,062** triangles. Lowering pixel ratio to 1.5 alone measured **19.3 ms** p95. Disabling shadows alone measured **18.7 ms** p95 despite cutting draw calls to 152. Both one-change experiments were reverted on the M1 because they did not improve the observed frame interval.

A separate temporary headless Chrome profile used `--use-angle=swiftshader`; the canvas reported `SwiftShader Device`, confirming software WebGL. With the full scene at 1760 × 1440, the five-second hold produced only **4 movement ticks** and **2,454.5 ms** p95 between sampled frames. Lowering pixels to 880 × 720 and disabling shadows yielded 9 ticks and 1,325 ms p95. Replacing asset models and photographic maps with plain shapes reduced this to 16 ticks and 824.1 ms p95. Removing the decorative plant models reduced triangles from about 115,000 to about 2,000. At a 440 × 360 render size, the repeat test recorded **108 movement ticks** in five seconds, **50.7 ms** frame-interval p95, about **128** draw calls and **1,942** triangles. Project import took **5,026 ms** in that run. The fixed held-key route reached Bedroom 2 at 3.20 m with no collision stop. A 0.75 pixel ratio measured 107.6 ms p95 and did not finish that timed route; 0.6 measured 73 ms p95 and stopped short of the bedroom. The 0.5 fallback remains in place.

The software Walk screenshot shows the avatar, bedroom furniture and openings clearly enough to follow the route, but it is visibly coarse. Export from that same software session produced a 3.7 MB GLB. Its JSON had **545 nodes, 402 mesh definitions and 108 stair-tagged nodes**, matching the full-detail browser export; Blender 5.2.1 imported **445 mesh objects and 313,520 vertices** from both files. The asset placeholders therefore affect the software preview, not its exported geometry.

The normal M1 path was retested after the fallback: 1760 × 1440 render pixels, **18.5 ms** frame p95, 460 calls and 1,041,098 triangles; the held-key stair route still reached 3.20 m without a stop. These are short local runs on one physical Apple M1 and one temporary SwiftShader process, not a second-device confirmation. The dev-only canvas probe reports renderer, frame-interval p95, CPU render-submission p95, calls and triangles while moving. Frame intervals include browser scheduling; CPU submission is not GPU time. The software fallback is selected through `WEBGL_debug_renderer_info`, so a browser that hides the renderer identity may not choose it. A browser without WebGL cannot run this Three.js viewer. Final frame and load targets still need confirmation on a second physical device.

A follow-up camera experiment tried a longer minimum boom distance and sampled whether the camera point intersected any modeled wall after each held-key route segment. It reached Bedroom 2, but a cutaway fourth-floor lintel intersected the eased camera point at the stair turn, and a wall dominated one bedroom frame. The distance change was reverted. Reducing only the opacity of the existing ray-blocking wall fade from 0.12 to 0.05 made the bedroom and avatar more legible in the same route, which again reached 3.20 m. This does not close the camera gate: a cutaway wall can still contain the camera position, and the exposed stair assembly looks unsupported against the open landscape. Those need geometry and camera review before showcase approval.
